# 智能商贸提单助手 规范

状态：已确认 ｜ 规模：完整 ｜ 创建：2026-11-14 ｜ 更新：2026-11-14
关联：[需求说明.md](需求说明.md)（需求原文）、[DESIGN.md](DESIGN.md)（技术方案）、[TASKS.md](TASKS.md)（任务清单）

## 目标

为大宗物资商贸业务的经办人提供一个提单助手：经办人用自然语言、单据照片或 Excel 表格描述订单，系统抽取要素、映射标准物料编码、关联合同并核算剩余额度，生成可核对的订单草稿，确认后一键生成正式销售或采购订单，审批人据此审核，全过程留有审计记录。本项目是课程实战练手，交付物以可运行的本地演示为准。

## 范围

- 做：
  - 三种提单输入：文本多轮对话、单据图片识别、Excel 批量导入，均支持销售订单和采购订单。
  - 物料俗称、简称、手写体识别结果到标准物料编码的映射与纠错。
  - 合同关联、额度四项统计、超额预警、必填缺失与异常字段高亮。
  - 草稿暂存与载入、一键正式提单、幂等防重、单号生成。
  - 全屏提单工作台与内嵌悬浮窗两种视图，二者双向切换且草稿状态不丢。
  - 一个模拟的"底层商贸系统"订单列表页（筛选、详情抽屉），悬浮窗挂在该页上，提单后列表联动刷新。
  - 登录鉴权、三类角色、按部门的权限隔离、操作审计日志。
  - 批量导入与数据中心页、主数据与系统配置页。
  - 示例数据集（合同、物料字典、别名、样例单据图片、样例 Excel）和需求中两个示例场景的端到端演示。
  - README 中的本机启动步骤和一个建表并灌入示例数据的初始化脚本。
- 不做：
  - 对接真实的第三方商贸系统；"底层商贸系统"由本项目内的模拟页面和数据表代替。
  - 自建或单独部署 OCR 引擎；图片识别直接使用视觉大模型。
  - 用户注册、找回密码、单点登录；用户由示例数据预置。
  - 移动端适配、多语言界面和暗色模式。
  - Docker 镜像与容器编排、生产部署、高可用。
  - 正式订单提交后由经办人主动撤销、作废或修改；只有审批人退回的订单可以修改后重新提交。
  - 主数据的删除和批量导入。
  - 大模型不可用时的规则抽取回退和离线 mock 模式。

## 使用场景

### US1 自然语言对话提单（P1）

经办人在全屏工作台输入一段提单描述（如"给中建八局科技城项目下 200 吨 HRB400E 螺纹钢，走 2026-WZ-089 合同，后天送到一号工地"）。系统抽取合同号、项目、物资、规格、数量和交期，把物资映射为标准物料编码，关联合同补全签约单位、收货地址和经办信息，写入固定业务属性，计算额度并在预览区展示草稿。缺少必填项时预览区高亮，对话中逐项追问；经办人补充或直接在预览区修改后，一键提单得到正式订单编号。

单独验证：只完成本场景时，用示例合同 2026-WZ-089 跑通需求原文的场景一，得到形如 `XSDD-WZGS-yyyyMMdd-001` 的订单号。

验收：

1. 假如合同 2026-WZ-089 存在且额度充足，当经办人输入上述描述，那么草稿中合同号、项目、物料编码 `STL-RB-400E-20`、数量 200 吨、交期为当前日期加 2 天，固定属性为"国内传统贸易 / 直发 / 传统贸易"，经办人、经办单位、创建人、创建时间取自当前登录用户。
2. 假如描述中没有合同号，当系统生成草稿，那么合同号字段标为待确认，对话流中出现针对合同号的追问。
3. 假如草稿完整，当经办人点击一键提单，那么生成唯一订单号，草稿状态变为已提交，提交按钮锁定。
4. 假如经办人在预览区修改数量，那么额度统计随之更新，再次对话时系统使用修改后的值。

### US2 单据图片识别提单与超额预警（P1）

经办人上传一张发货签收单、磅单或采购合同照片。系统识别物资名称、规格、数量、金额和到货单位，把俗称纠正为标准物料编码，输出识别卡片并同步到预览区。本次金额超出合同剩余可下金额时，预览区顶部出现红色超额横幅；经办人填写备注后仍可提交，订单进入待特批状态。

单独验证：用示例签收单图片（42.5 水泥 500 吨，金额 22 万元，合同剩余 15 万元）跑通需求原文的场景二，得到待特批订单。

验收：

1. 假如上传示例签收单图片，那么识别卡片显示 42.5 水泥、500 吨、22 万元，物料映射为字典中的标准编码。
2. 假如本次金额超出合同剩余金额，那么预览区出现超额横幅，未填备注时不能提交。
3. 假如经办人填写备注后提交，那么订单生成正式编号，状态为待特批，订单带超额标记。

### US3 Excel 批量提单（P2）

经办人下载导入模板，填写多行订单后拖拽上传。系统逐行解析校验，展示校验结果表，异常行标红并给出原因；经办人行内修改后重新校验该行，最后批量提交。

单独验证：用示例 Excel（含合同号错误、单价缺失、超额三类异常行）完成导入、修正和批量提交。

验收：

1. 假如上传示例 Excel，那么三类异常行分别标红并显示原因，正常行标为可提交。
2. 假如同一合同在一批中出现多行，那么后面的行按前面行占用后的剩余额度判断是否超额。
3. 假如修正异常行后点击批量提交，那么每行生成一笔正式订单，单行失败不影响其他行，结果表显示每行的订单号或失败原因。

### US4 悬浮窗提单与商贸系统联动（P2）

经办人在模拟商贸系统的订单列表页点击右下角悬浮球，展开悬浮窗进行多轮对话提单，可收起或切到全屏工作台继续，草稿和对话不丢。提单成功后订单列表自动刷新，经办人可打开详情抽屉核对完整信息。

单独验证：在订单列表页通过悬浮窗完成一笔提单，切换到全屏再切回，最后在列表中打开该订单详情。

验收：

1. 假如悬浮窗中已有进行中的草稿，当切换到全屏工作台再切回，那么对话记录和草稿内容一致。
2. 假如悬浮窗中提单成功，那么订单列表无需手动刷新即出现该订单。
3. 假如打开订单详情抽屉，那么能看到订单主档、物资明细和合同额度信息。
4. 订单列表支持按单据类型、状态、合同号、日期范围筛选。

### US5 订单审批（P2）

审批人查看本部门待审订单，核对合同额度与超额标记后执行审核通过、退回修改或驳回。被退回的订单回到经办人手中，修改后重新提交。

单独验证：审批人登录后审核 US2 生成的待特批订单，再退回另一笔订单并由经办人修改重提。

验收：

1. 假如审批人登录，那么只能看到本部门的待审订单（已提交、待特批）。
2. 假如审批人审核通过，那么订单状态变为已审核并记录审计日志。
3. 假如审批人退回订单并填写退回意见，那么订单状态变为退回，经办人能看到退回意见并修改后重新提交。
4. 假如审批人驳回订单并填写驳回原因，那么订单状态变为驳回，不能再修改或提交。

### US6 主数据与系统配置（P3）

管理员新增和修改合同台账、物料编码字典与别名、额度规则和大模型调用参数，查看操作审计日志。

单独验证：管理员新增一条物料别名后，经办人用该别名提单能映射到对应物料。

验收：

1. 假如管理员为某物料新增别名，那么后续对话中的该别名映射到该物料编码。
2. 假如管理员打开审计日志，那么能按操作人、动作、时间筛选。

## 页面

按角色显示导航：业务经办人看到商贸订单列表、全屏提单工作台、批量导入与数据中心；业务审批人只看到商贸订单列表；系统管理员只看到主数据与系统配置。

- 登录页：账号密码登录，登录后按角色进入默认页面（经办人、审批人进入商贸订单列表，管理员进入主数据与系统配置）。
- 商贸订单列表页（模拟底层商贸系统）：
  - 销售订单、采购订单两个页签，筛选栏按状态、合同号、日期范围筛选；审批人默认筛选"待我审核"。
  - 列表列：单据编号、合同号、签约单位、工程项目、总金额、状态、超额标记、经办人、创建时间。
  - 详情抽屉：订单主档、物资明细、合同履约配额看板、审批意见与审计流水。审批人在抽屉底部执行通过、退回、驳回；经办人打开自己被退回的订单时可点击"修改"，订单载入全屏工作台。
  - 右下角悬浮球：仅对经办人显示，展开为悬浮窗。
- 悬浮窗：对话气泡流、文本输入框、四个快捷操作，以及一张精简草稿卡片（单据类型、合同号、签约单位、物资与数量、本次金额、剩余可下金额、超额与缺失提示）。卡片上可一键提单；逐字段编辑、图片识别和 Excel 导入需切换到全屏工作台。窗口可收起为悬浮球。
- 全屏提单工作台：左侧为多模态提单交互区（文本对话、图片识别、Excel 导入三个面板切换，快捷操作标签，消息气泡流）；右侧为订单草稿预览与核验区（状态胶囊、额度统计卡片、超额横幅与提醒、基本信息网格、产品明细表、提单操作栏：保存草稿、一键提单、切回悬浮窗）。
- 批量导入与数据中心页：模板下载、拖拽上传、校验结果表（每行状态、异常行标红及原因、行内修改后重新校验）、批量提交；下方为导入记录列表（文件名、导入时间、总行数、成功行数、失败行数），点开可查看该批次每行的订单号或失败原因。
- 主数据与系统配置页：合同台账、物料字典与别名、参数配置、审计日志四个页签。

## 边界情况

- 物料无法映射到字典中的任何编码：物料编码留空并标为待确认，系统列出候选供经办人选择，不生成字典外的编码。
- 合同号不存在或不属于当前用户所在部门：合同字段标红，提示原因，不能提交。
- 合同类型与订单类型不符（用销售合同下采购订单）：标红提示，不能提交。
- 单价缺失：对话和图片提单中，物料在合同物料明细内时自动取合同约定单价并注明来源；物料不在合同内，或 Excel 导入行未填单价时，单价字段高亮为待确认，不能提交。
- 交期早于今天或晚于合同到期日：交期字段高亮并说明原因，不能提交。
- 大模型或视觉模型调用失败或超时：对话流显示失败提示，已有草稿保持不变，经办人可在预览区手工编辑字段完成提单；不提供规则抽取回退。
- 图片无法识别出任何物资信息：提示重新上传，不生成草稿。
- 上传的 Excel 不符合模板列结构：整份文件拒绝并提示缺少哪些列。
- 上传的 Excel 没有数据行：提示文件中没有可导入的订单。
- 两个经办人同时提交占用同一合同额度：后提交者按最新剩余额度重新判定是否超额。
- 网络抖动导致同一草稿重复提交：只生成一笔订单，重复请求返回同一订单号。
- 登录过期：提交请求被拒，前端跳转登录，草稿保留。
- 等待大模型或视觉模型返回时：对话流显示处理中状态，输入框和提单按钮暂不可用。
- 列表、导入记录、审计日志没有数据时：显示空状态说明，不显示空表格。

## 需求

基础能力

- FR-001 用户用预置账号登录，未登录访问任何业务接口均被拒绝。
- FR-002 提单、提交、查询、审批操作校验当前用户所属部门，不能读写其他部门的单据和合同。
- FR-003 草稿保存、图片识别、Excel 导入、正式提单、审批操作写入审计日志，记录操作人、动作、输入原文或图片 SHA-256、单据号和时间戳。
- FR-004 草稿可保存，经办人可通过"继续上次"载入最近一份未提交草稿。

智能提单

- FR-010 识别提单意图：新建销售订单、新建采购订单、修改当前草稿、继续上次、使用帮助。
- FR-011 从自然语言中抽取合同号、工程项目、物资品名、规格、数量、单位、单价和交期；相对日期按服务端当前日期换算。
- FR-012 多轮对话中，后续轮次的补充或修改合并到当前草稿，而不是新建草稿。
- FR-013 自动填充固定业务属性：业务名称"国内传统贸易"、采购模式"直发"、业务标签"传统贸易"。
- FR-014 依据登录身份自动绑定经办人、经办单位、创建人和创建时间。
- FR-015 识别发货签收单、磅单、采购合同图片中的物资名称、规格、数量、单位、金额和到货单位，输出识别卡片，可一键应用为草稿。
- FR-016 物资名称（含俗称、简称、识别误差）映射为物料字典中的标准编码与规范名称；无法确定时给出候选并标为待确认。物料编码只能来自物料字典。
- FR-017 提供 Excel 导入模板下载，模板一行对应一笔只含一种物资的订单；上传后逐行解析并校验合同、物料、数量、单价、交期。

履约核验

- FR-020 按合同号关联合同主数据，补全签约单位、工程项目、收货地址、联系人。
- FR-021 计算并展示合同总金额、累计已下金额、剩余可下金额、剩余可下数量（主计量单位）和本次占用金额。
- FR-022 本次订单金额超出合同剩余可下金额时，预览区显示超额横幅并记录超额标记；提交前必须填写备注，提交后订单进入待特批状态。
- FR-023 必填字段缺失或取值异常（单价缺失、交期早于今天或晚于合同到期日、合同不匹配、物料未映射）时在预览区高亮并说明原因，对话流中针对缺失项追问。
- FR-029 对话和图片提单未给出单价时，按单据金额除以数量计算；仍无单价且物料在合同物料明细内时，取合同约定单价并在字段旁注明“单价取自合同约定单价”。Excel 导入不自动补单价。
- FR-024 采购订单与销售订单分别关联对应类型的合同。
- FR-025 本次数量超出合同剩余可下数量时，作为异常字段高亮提示，不触发超额横幅和待特批。
- FR-026 除驳回外，已提交、待特批、已审核、退回状态的订单都计入合同累计已下金额和数量；订单被驳回后释放其占用的额度。
- FR-027 单价偏离该物料公允价超过允许比例时，单价字段以提醒级别高亮并显示公允价，不阻止提交。
- FR-028 本次提交后合同剩余可下金额占合同总金额的比例低于配额阈值时，预览区显示提醒级别的额度预警，不阻止提交。

商贸协同

- FR-030 预览区展示状态胶囊、额度统计卡片、超额横幅、基本信息网格、产品明细表和提单操作栏。
- FR-031 预览区字段可直接编辑，编辑结果与对话中的草稿双向同步。
- FR-032 一键提单：提交前在服务端重新校验必填项和额度，成功后生成唯一单号（销售前缀 XSDD、采购前缀 CGDD，格式 `前缀-单位代码-yyyyMMdd-三位流水号`），草稿状态推进为已提交或待特批。
- FR-033 同一草稿重复提交只生成一笔订单，提交成功后按钮锁定。
- FR-034 正式订单与物资明细同步写入模拟商贸系统的订单数据。
- FR-035 模拟商贸系统订单列表支持按单据类型、状态、合同号、日期范围筛选，点击订单打开详情抽屉。
- FR-036 Excel 批量提交时每行独立成单，单行失败不影响其他行，结果逐行展示。
- FR-037 审批人可对本部门已提交、待特批订单执行审核通过、退回修改或驳回；退回和驳回必须填写意见。
- FR-038 被退回的订单由原经办人修改后重新提交，沿用原单号；重新提交时在服务端重新校验必填项和额度（计算剩余额度时排除该订单自身原有的占用），按结果进入已提交或待特批，并同步更新模拟商贸系统中的记录。

双模态交互

- FR-040 订单列表页右下角悬浮球展开悬浮窗，悬浮窗支持收起、切换全屏和多轮对话提单。
- FR-041 全屏工作台提供文本对话、图片识别、Excel 导入三个输入面板，以及新建销售订单、新建采购订单、继续上次、使用帮助四个快捷操作。
- FR-042 悬浮窗与全屏工作台双向切换时，对话记录与草稿保持一致；浏览器刷新后恢复当前会话。

## 关键实体

- 部门：经办单位，含单位代码（用于单号），用户与合同都归属某个部门。
- 用户：属于一个部门，角色为业务经办人、业务审批人或系统管理员之一。
- 签约单位：客户（销售合同对方）或供应商（采购合同对方）。
- 工程项目：含收货地址、联系人，与合同关联。
- 合同：合同号、类型（销售/采购）、签约单位、工程项目、总金额、到期日、经办部门，含若干合同物料明细（物料、合同单价、合同数量）。
- 物料：标准物料编码、规范名称、规格、主计量单位、品牌、公允价；一个物料有多个别名。
- 草稿：属于一个会话和一个经办人，含订单主档字段、物资明细、待确认字段列表和状态（草稿未提交、待确认）。
- 订单：由一个草稿生成（一对一），含单据编号、类型、合同、主档字段、物资明细、超额标记、备注、状态（已提交、待特批、已审核、退回、驳回）。
- 导入批次：一次 Excel 上传，含文件名、导入人、时间、总行数、成功与失败行数，以及每行的解析结果和生成的订单。
- 审计记录：操作人、动作、输入原文或图片哈希、单据号、时间戳。
- 系统参数：固定业务属性、公允价允许偏离比例、履约配额阈值、模型参数。

## 成功标准

- SC-001 需求原文的两个示例场景各能从输入到生成正式订单号完整演示，且每一步都有截图。
- SC-002 示例数据中的物料俗称与简称（每个物料至少一个别名）全部映射到正确的标准编码，没有出现字典外编码。
- SC-003 对同一合同并发提交 10 笔订单，累计占用金额与逐笔计算结果一致，没有两笔订单共用同一份剩余额度而都判定为未超额。
- SC-004 对同一草稿连续发出 5 次提交请求，只生成 1 笔订单，5 次响应返回相同订单号。
- SC-005 示例 Excel 中预设的每一个异常行都被标红，正常行全部提交成功。
- SC-006 悬浮窗与全屏工作台来回切换 3 次后，对话条数和草稿字段与切换前一致。
- SC-007 经办人和审批人无法通过接口读取其他部门的订单或合同（接口返回 403 或 404）。
- SC-008 对话提单单轮响应在 15 秒内返回（依赖外部大模型，按本机网络条件测量）。

## 约束

- C-001 数据库使用本机 MySQL80 服务，默认停止，使用前手动启动。
- C-002 物料编码只能来自物料字典，大模型不得生成字典外的编码。
- C-003 额度核验与单号生成在同一事务内加行锁完成。
- C-004 真实密钥只放 `.env`，不写入代码、文档、日志或提交。
- C-005 课程提交时按"组名_姓名_项目_行业"另行复制改名，只放代码（不带依赖）和测试截图。
- C-006 实现范围以本规范为准，技术方案以 DESIGN.md 为准；需求或方案变更时同步更新对应文档，并在本规范的决策记录中登记。
- C-007 至少一个示例场景完成端到端演示（需求原文验收要求）。
